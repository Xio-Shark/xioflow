# Parallel Decoupled Tasks

> **Purpose**: Split complex work into independently verifiable children with an explicit dependency graph, then dispatch ready sets safely.

---

## When to Use

- One request has **several deliverables** that can be verified independently
- Some children can run **in parallel**; others must wait on siblings
- You need a clear **ready / blocked** view before spawning agents

If the work is a single serial deliverable, stay with one task — do not invent a graph.

---

## Tree vs dependency graph

| Concept | Field / structure | Means |
|---------|-------------------|--------|
| Ownership tree | `parent` / `children` | Who owns the map and integration |
| Sibling deps | `depends_on: string[]` | Directory names that must be `completed`/`done`/archived first |
| Isolation | `isolation: "worktree" \| "shared"` | How safe parallel writers are |

**Authoritative**: `task.json`. Markdown `## Dependencies` is a human/agent-readable projection.

---

## Dual-write contract

In each child `task.json`:

```json
{
  "depends_on": ["07-16-sibling-a"],
  "isolation": "worktree"
}
```

And in that child's `prd.md` (or `implement.md`):

```markdown
## Dependencies
- depends_on: `07-16-sibling-a`
- isolation: worktree
- parallel_group: wave-1
```

Legacy tasks missing these fields ≡ `depends_on: []` and unset isolation (serial behavior unchanged).

`task.py drift <parent>` warns on mismatch. Drift does **not** block `ready`.
json→markdown sync is reserved for a later phase. Phase B may set
`parallel.drift_fail_closed: true` so `dispatch-ready --yes` refuses to spawn
while drift is present.

---

## Isolation rules

| Value | Use when | Parallel rule |
|-------|----------|---------------|
| `worktree` | Code / shared types / tests will change | Each worker gets its own worktree/branch; set `worktree_path` before auto-dispatch |
| `shared` | Docs, research, readonly analysis | Same cwd allowed |
| unset | Serial or not yet planned | Do not assume parallel safety |

**Never** same-cwd multi-writer for code tasks.

### write_scope (planning-time conflict guard)

Each code child should declare repo-relative globs in `task.json`:

```json
"write_scope": ["src/runtime/explore/**", "docs/STATUS.md"]
```

Dual-write the same list under `## Dependencies`. Rules:

- `isolation=worktree` → non-empty `write_scope` required at `plan-import`
- Edge-free sibling pairs (neither reaches the other via `depends_on`) with
  intersecting scopes → **fail-closed** at `plan-import` and again before
  `dispatch-ready --yes`
- Intersection is a **conservative approximation** (expand against current repo
  files + prefix heuristics). May miss files not yet on disk; false positives
  → narrow globs, add an edge, or merge tasks
- Config: `parallel.scope_fail_closed` (default `true`; `false` → warn and continue)
- Legacy tasks without `write_scope` do not fail; worktree dispatch emits a warning

## Planning checklist

1. Complex multi-deliverable → parent + children.
2. For each child pair: shared files/types/tests? Yes → edge or merge; No → parallel candidate.
3. Prefer a `parallel-plan.v1` JSON + one-shot import (avoids N manual creates):
   ```bash
   python3 ./.trellis/scripts/task.py plan-import <parent-dir> plan.json        # dry-run
   python3 ./.trellis/scripts/task.py plan-import <parent-dir> plan.json --yes  # materialize
   ```
   Import validates schema / slug collisions / missing deps / cycles (fail-closed, zero writes),
   dual-writes `## Dependencies`, and pre-creates `git worktree` under `.trellis/worktrees/<dir>`
   for `isolation=worktree` (fills `worktree_path` + `branch`).
4. Or write `depends_on` + `isolation` to `task.json` and dual-write markdown by hand.
5. Human reviews parallel groups (default). Then:
   ```bash
   python3 ./.trellis/scripts/task.py ready <parent-dir>
   python3 ./.trellis/scripts/task.py drift <parent-dir>
   python3 ./.trellis/scripts/task.py dispatch-ready <parent-dir>        # dry-run plan
   python3 ./.trellis/scripts/task.py dispatch-ready <parent-dir> --yes  # spawn after confirm
   ```
6. When all required children complete → `task.py integrate <parent>` (merge + verify). Conflicts → serial fix; do not pretend parallel succeeded.

## Demo path (A → B → C → Integrate)

Example: parent with three children

- `child-a`: `depends_on: []`, `isolation: worktree`, `worktree_path: ../wt-a`, `branch: feat/a`
- `child-b`: `depends_on: []`, `isolation: worktree`, `worktree_path: ../wt-b`, `branch: feat/b`
- `child-c`: `depends_on: [child-a, child-b]`, `isolation: worktree`

Wave 1: `ready` / `dispatch-ready` lists A and B; C is blocked.  
Confirm → `dispatch-ready --yes` spawns A and B via default worker (`xio`, or `channel` fallback) in separate cwds.  
Wave 2: after A and B complete, dispatcher recomputes and spawns C.  
Failure: failed child does **not** unlock dependents; parent archive/complete is refused.  
Integrate: after all required children complete:

```bash
python3 ./.trellis/scripts/task.py integrate <parent-dir>          # merge + verify
python3 ./.trellis/scripts/task.py integrate <parent-dir> --dry-run
```

Conflict → non-zero exit + optional serial fix task stub; never same-cwd multi-writer force-merge.
Parent archive requires `meta.integrate_ok` (or noop) when any child used `isolation=worktree`.

Cycle in the parent subgraph → fail closed (exit non-zero).

---

## Phase C — default worker = xio

- Config `parallel.worker` defaults to `xio`. Override with `channel` (or aliases `claude`/`codex`) for `trellis channel run`.
- Spawn injects **Active task** path plus `prd.md` / `design.md` / `implement.md` / jsonl (truncated by `parallel.context_max_chars`).
- `isolation=worktree` still requires a pre-existing `worktree_path` (dispatch does not invent worktrees).
- If `xio` is missing and `parallel.worker_fallback: channel` (default), fall back with a warning.
- **MergeGate contract**: xiocode MergeGate stays user-ask / never auto-merge. Trellis owns `depends_on`; parent merge is `task.py integrate` (L4), not an xio auto-merge.

---

## Full form — Integrate (L4)

Owns:

- Parent complete gate (required children done + no failed children + integrate when worktree kids exist)
- `task.py integrate <parent>`: merge child branches into `base_branch`, run `parallel.verify_command`
- Conflict → abort merge, serial fix guidance / optional fix-task stub

Does **not** own: `dispatch-ready` waves (B) or xio adapter defaults (C).

Parents with no `isolation=worktree` children: integrate is a successful no-op.

## CLI reference

```bash
python3 ./.trellis/scripts/task.py ready <parent-dir>
python3 ./.trellis/scripts/task.py drift <parent-dir>              # warn; may exit non-zero
python3 ./.trellis/scripts/task.py deps <task-dir>
python3 ./.trellis/scripts/task.py plan-import <parent-dir> <plan.json> [--yes]
python3 ./.trellis/scripts/task.py dispatch-ready <parent-dir>     # dry-run plan (default)
python3 ./.trellis/scripts/task.py dispatch-ready <parent-dir> --yes
python3 ./.trellis/scripts/task.py integrate <parent-dir>          # L4 merge + verify
python3 ./.trellis/scripts/task.py integrate <parent-dir> --dry-run
```

Ready predicate: every `depends_on` entry is completed/done/archived; child status is actionable (`planning` / `pending` / `in_progress`); no cycle. `failed` children stay skipped and do not unlock dependents.

### Config (`.trellis/config.yaml`)

```yaml
parallel:
  auto_confirm: false       # if true, dispatch-ready spawns without --yes
  drift_fail_closed: false  # if true, --yes refuses when drift is present
  scope_fail_closed: true   # if true, --yes refuses on write_scope overlap
  max_concurrency: 8        # wave spawn cap; 0 = unlimited (legacy)
  max_retries: 0            # extra attempts after first failure
  agent: implement          # channel agent role (when worker=channel)
  timeout: 30m
  worker: xio               # Phase C default; set channel to force trellis channel run
  worker_fallback: channel  # when xio missing; set none/false to fail closed
  verify_command: "npm run check"  # L4 integrate verify
  context_max_chars: 24000  # xio -p artifact budget
```

Tests may set `TRELLIS_DISPATCH_BACKEND=mock` to skip the real `trellis`/`xio` CLI.

## Out of scope

- Same-cwd multi-writer parallel code edits
- Claiming perfect automatic decoupling
- Implementing the DAG engine inside an app worker (e.g. xiocode) — Trellis owns orchestration
- Auto-resolving all git merge conflicts
