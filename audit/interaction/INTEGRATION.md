# Agent—系统交互的职责边界与集成决定

2026-11-03，研究层决定：**先保留当前原型与负结果，不向稳定ISA新增观察语言、订阅内核或动作指令。** 已有机制证据支持继续研究确定性执行层；完整模型成本收益、动作模型表现和跨模型迁移尚未得到验证。

## 当前证据支持的职责划分

模型负责理解用户目标、识别需要的对象和证据、提出关注条件，并处理超出已声明策略的异常。宿主负责采样、版本与身份核对、机械等待、超时、允许范围内的动作执行、费用预留和资源回收。独立检查器核对目标后置条件，动作accepted、命令exit code和日志文本只作为中间事实。

这是可检验的职责划分，不是新的OS架构已经成立。20条已有模型条件回放通过，但尚未测试用它替代模型中间判断后，完整成本和异常处理是否仍有收益。62/65条成功轨迹继续观察也不意味着每次额外查询都可安全省略。

| 选择 | 当前依据 | 不应推断的结论 |
| --- | --- | --- |
| 短小完整数据可直接读取 | 原只读模型对照中full请求更少；小页有额外往返 | 所有大数据或动态状态都应全读 |
| 已知条件的机械等待交给宿主 | 同等发现门禁下，脚本通知从200降为91；已有条件回放20/20 | 模型调用或总费用必然下降 |
| 去重轮询作为必要基线 | 本轮与事件方案通知相同，事件方案机制扫描更多 | 事件机制普遍无效 |
| 事件提示后重读并周期核对 | 丢提示场景仍能收敛，事实从配置及探针取得 | 事件流已捕获每个瞬时状态 |
| 动作后查实际生效 | reload-noop能被独立检查识别，24个脚本终局正确 | 模型已能可靠完成72项动作对照 |

## 与当前Xioflow能力的候选映射

下表依据本次只读核对的[registry.json](../../spec/isa-v1/registry.json)。这是后续集成路径，实验当前直接使用Node子进程及临时文件，未接入这些生产能力。

| 研究职责 | 现有opcode与事实标记 | 集成仍需补足 |
| --- | --- | --- |
| 启动、身份及运行事实 | proc.spawn → driver.identity_and_spawn_gate；proc.inspect → driver.process_facts | 将研究instanceId与宿主实际运行身份可靠绑定 |
| 进程终止与回收 | proc.wait → driver.tree_settlement_and_exit；proc.signal → driver.stop_confirmation | 进程终止与应用HTTP就绪是不同后置条件 |
| 内容与版本事实 | fs.read → filesystem.content_and_hash | 源版本、新鲜度和业务字段之间的显式关联 |
| 写入及效果证据 | fs.write → filesystem.hash_after_write；fs.patch → filesystem.diff_and_hash | local_atomic不能替代跨任意写者的原子CAS，也不能证明服务已加载 |
| 可恢复工作区变更 | workspace.snapshot → workspace.tree_fingerprint；workspace.rollback → workspace.rollback_coverage_and_fingerprint | 文件回滚不能自动恢复外部服务状态，需任务级补偿和验证 |

不改变proc.wait的终止语义来表示应用ready。应用层HTTP检查、日志解释和配置加载应先放在研究适配器中，使用现有可审计调用与最终检查。权限判断不能从查询投影或模型提交的where条件推导。

## 进入集成的门禁

先在原冻结协议下补齐P2未尝试项，保留两次服务失败；P3完成同等动作能力的模型对照，记录实际写入、错误尝试和恢复；P4对确定性观察策略做前瞻配对对照，若费用与正确性优势不能复现则保留负结果。具备这些证据后才另定生产适配范围，核对取消、外部写者、身份复用、观察失效与恢复语义。本次不修改稳定内核，也不把后续集成工作计为已实现。
