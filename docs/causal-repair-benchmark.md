# 因果修复可复现基准

运行 `pnpm benchmark:causal`，在真实 Git 工作区、SQLite journal、snapshot / fork 和 OCC 提交上比较三种策略。命令先构建，再输出 JSON；不需要模型 API、网络或新增依赖。可指定试验轮数、独立分支数和每个派生工具的 SHA-256 迭代次数：

```sh
pnpm benchmark:causal 3 4 1000
# 需要纯 JSON 时，在构建完成后直接运行：
node scripts/benchmarks/causal-repair.mjs 3 4 1000 > report.json
```

这是一项确定性文件任务基准，并非通用 agent 成功率评测。实现位于 `src/testing/causal-repair-benchmark.ts`，CLI 位于 `scripts/benchmarks/causal-repair.mjs`，属于仓库评测入口，不是新的公共运行时 API。

## 任务与对照

每个分支由三个有因果依赖的工具组成：读取输入 → 确定性派生计算 → 写入输出。首先执行并 OCC 提交全部分支，随后改变一个输入；第 `trial` 轮改变 `trial % branches` 分支。每个策略使用全新的仓库与 domain，初始内容、工具实现和扰动完全一致；轮换策略顺序，降低固定运行顺序的影响。

| 策略 | 扰动后行为 | 成功条件 |
| --- | --- | --- |
| `full-rerun` | 在新事务中重新执行全部工具并 OCC 提交 | 全部输出与当前输入对应 |
| `incremental-repair` | 读取全部源观测发现变化；验证独立输入及已物化输出；只执行因果失效闭包并 OCC 提交 | 与完整重跑逐项一致 |
| `unchecked-reuse` | 不验证、不重算，保留全部旧输出 | 用同一个 oracle 检查；预期受扰动分支失败 |

最后一项是刻意构造的“不校验直接复用”负对照，不能代表所有无监督 agent。所有依赖由固定任务显式声明，派生工具没有外部副作用。测试覆盖轮换扰动、多分支和全部节点失效的单分支情形。

## 指标口径

- `executionToolCalls`：扰动之后实际执行的 read / derive / write 回调次数。计数来自同一个真实工具实现，不从计划节点数推算。
- `changeDetectionReads`：定位变化输入所做的文件读取次数。
- `reuseValidationReads`：新事务 fork 中校验独立输入和已有输出的文件读取次数。验证失败抛错，不能静默复用。
- `reusedNodes`：保留的历史节点数。此值不是已经节约的 token。
- `elapsedMs`：从扰动后查询图开始，到策略完成 OCC 提交和快照回收；包含变化检测、复用验证、工具执行、journal 和事务开销。排除各策略共同的初始建库/初次执行、扰动注入、结果 oracle 与最后测试目录清理。不承诺 CPU 计算减少就一定更快。
- `correctOutputs` / `totalOutputs` / `success`：用当前全部输入重新计算期望值，检查每个实际输出；只有全部正确才算该次成功。`outputHashes` 支持逐分支对比。`summary` 报告各策略成功率、平均调用次数和耗时中位数。
- `commitValidation`：报告实际 OCC 校验等级，可能为 `files` 或 `write_only`；无提交的负对照为 `null`。该任务在扰动后没有后台并发写入，不据此宣称解决任意并发情形。
- `modelTokens: null`：没有模型调用，不推断 token、模型质量或真实 agent 成本收益。

默认四分支时，完整重跑执行 12 次工具，增量执行 3 次工具，同时增加 4 次变化检测读取和 6 次复用验证读取。可以说**执行工具次数减少 75%**，不能说总操作数减少 75%；这些操作成本也不等价。较轻任务可能被事务和验证成本主导。耗时应报告实测数据，避免作为 CI 中的硬性加速断言。

JSON 包含参数、Node/Git 版本、平台及全部原始样本。相同参数保证内容、扰动与调用计数可复现，不保证墙钟时间一致。正式性能对比应在空闲机器上增加轮数，并记录 CPU、文件系统和缓存条件；本任务没有模拟网络或 LLM 延迟。

## 本次实测样本（2026-10-08）

[完整 JSON](benchmarks/causal-repair.sample.json) 来自 Linux arm64、Node v22.23.3、Git 2.47.3；参数为 3 轮、4 分支、每次派生 1000 次哈希迭代。该次运行未与测试或构建并行。

| 策略 | 全部输出正确的试验 | 执行工具次数/轮 | 检测 + 复用验证读取/轮 | 端到端中位数 |
| --- | --- | --- | --- | --- |
| 完整重跑 | 3/3 | 12 | 0 + 0 | 95.63 ms |
| 增量修复 | 3/3 | 3 | 4 + 6 | 86.45 ms |
| 不校验复用 | 0/3 | 0 | 0 + 0 | 0.18 ms |

增量修复和完整重跑的全部输出哈希一致；负对照每轮有一个输出错误。这三个样本仅展示该固定任务上的结果，不能外推真实 agent 成功率或稳定加速比例。
